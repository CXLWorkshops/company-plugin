# Content Repurposing Frameworks

Frameworks for turning one source asset into many platform-native pieces. The content engine behind [[b2b ai tactics newsletter]], where the newsletter issue is the primary source asset everything else derives from.

---

## Core models

**Hub-and-Spoke (Pillar → Derivatives)** — one substantial hub asset (a newsletter issue) spun into many spokes (LinkedIn posts, carousels, shorts, a blog post). Formalize the spoke list per hub so repurposing isn't an afterthought.

**Atomic content / Atomization** — break one big idea into its smallest standalone units (a stat, a quote, a single tactic, a before/after), each becoming its own post. The model for *how* to fragment a newsletter into 8–10 pieces without them feeling thin.

**Create Once, Publish Everywhere (COPE)** — produce the source once, adapt format per channel. The philosophy; hub-and-spoke is the structure.

**Content Pyramid (Pillar → Micro-content)** — one pillar piece sliced into dozens of platform-native micro pieces, then engage from them. Discipline: *platform-native* adaptation, not copy-paste.

---

## Adaptation & distribution layers

**Repurposing matrix** — map each source asset across **formats** (text / visual / video / audio) × **channels** (LinkedIn / IG / YouTube / blog). One grid per issue guarantees varied formats, not the same post everywhere.

**Skyscraper / Refresh-and-Repurpose** — repurpose *across time*: resurface and update high-performers. Feeds the engine without always needing net-new ideas.

**Distribution-first (PESO: Paid / Earned / Shared / Owned)** — decide where each derivative lives before making it, so creation serves distribution.

---

## Recommended workflow

**Hub-and-Spoke + atomization checklist, run weekly.** For each newsletter issue, predefine the spoke set below. Turns "repurpose latest issue" from a vague intention into a repeatable production line and closes the project risk "producing content without strong repurposing workflows."

### Per-issue repurposing checklist

- [ ] **1 blog post** — SEO-optimized version of the issue
- [ ] **3–4 LinkedIn posts** — one per atomic tactic / stat
- [ ] **1 carousel** — visual breakdown of the core framework
- [ ] **2–3 short-form video scripts** — hooks pulled from the strongest atoms
- [ ] **Social snippets / quotes** — pull-quotes and stats for distribution
- [ ] **Schedule across channels** — map each piece to its platform + date

---

## Through-line

Don't create per channel — create once, then atomize and adapt. The source asset is the highest-signal piece; everything downstream is a platform-native cut of it.
